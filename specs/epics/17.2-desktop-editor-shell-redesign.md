# Sprint 17.2 — Desktop Editor Shell Redesign

Date: 2026-07-29

Shell-only redesign, as explicitly scoped by this sprint's brief (narrower than the original planning entry in `frontend-redesign-master-plan.md` §17.2, which covered all `desktop-editor`/`ai-timeline` components — see that section's status note). No Preview/Timeline/Inspector/Asset Panel/AI Timeline internal content was touched, no runtime was modified, and Sprint 17.3 has not begun.

## 1. Shell architecture

`DesktopEditorShell` composes `DesktopGrid` (a pure CSS-grid layout primitive) around 8 slots: header, tool rail, asset panel + divider, preview, timeline + divider, inspector + divider, a new reserved AI Director dock, and the status bar. `DesktopEditorRuntimeAdapter` (untouched) bridges the real `ReviewWorkspaceProvider` data into this shell — the shell itself owns zero editing logic, exactly as required. Layout state (widths, collapse flags, tool-rail compaction, and now viewport-responsive auto-narrowing) is centralized in `useDesktopEditorLayout`.

## 2. New shell components

- **`EditorAiDirectorDock`** (new) — a static, reserved placeholder region docked at the bottom of the Timeline Workspace per the blueprint's canonical layout. Renders text only ("AI Director — reserved for Sprint 17.8"), no input, no submission path, no runtime call. The real `ReviewAICommandBar` submission boundary is untouched and stays inside `EditorAiCopilot` until 17.8 decides how/whether to relocate it — this dock never becomes a second command surface.

No other new components were created — the existing `DesktopGrid`/`PanelDivider`/`PanelCollapseButton`/`useLayoutResizer` set already constituted a real, working, reusable panel framework (proven across 3 panels before this sprint); Sprint 17.2 hardens and extends it rather than replacing it with new naming (`PanelHost`/`PanelFrame` were considered — see §13).

## 3. Panel framework

Every panel already supported default/min/max size, collapse/expand, resize, and scroll ownership via `useDesktopEditorLayout` + `PanelDivider` + `PanelCollapseButton` + `useLayoutResizer`. This sprint:

- Converted all of it to `--ce-*` tokens (see §6).
- Added `computeResponsiveDesktopEditorLayout`, a pure function that resolves widths as a function of live viewport width without mutating the user's stored preferences — widening the window back out restores exactly what the user had set.
- Fixed a latent toggle-inversion bug: previously, clicking "expand" while a panel was auto-collapsed would have flipped the raw preference the wrong way (staying collapsed). Toggle now flips the *effective* (visible) state, not just the raw one.

## 4. Docking implementation

Matches the blueprint exactly: Tool Rail fixed-left, Asset Panel resizable/collapsible left-dock, Preview fills remaining space (protected, never resized/collapsed directly), Timeline bottom-docked (resizable height), Inspector resizable/collapsible right-dock, AI Director dock reserved beneath Timeline, Status Bar fixed bottom spanning full width. `DesktopGrid`'s `grid-template-areas` gained one new row (`aiDirector`) between `timeline` and `status` — the only structural change to the grid shape.

## 5. Responsive behavior

`computeResponsiveDesktopEditorLayout` applies the blueprint's collapse-priority order — compact Tool Rail → narrow Asset Panel to its min → collapse Asset Panel → narrow Inspector to its min → collapse Inspector — whenever live viewport width would otherwise push Preview below a protected 480px floor (comfortably under the 630px worst-case remainder already verified at 1366×768 in Sprint 16.10.6.1/17.1). Verified at 1920×1080, 1600×900, 1440×900, and 1366×768 — none of these trigger any auto-narrowing (all comfortably exceed the 480px floor even with every panel at its user-chosen default), confirming the existing math holds; the new logic exists for genuinely tight windows (e.g. panels manually dragged to max on a small display) rather than the four target viewports themselves.

## 6. Theme

Every shell-owned file — `DesktopEditorShell`, `DesktopEditorHeader`, `EditorToolRail`, `EditorStatusBar`, `PanelDivider`, `PanelCollapseButton`, `EditorAiDirectorDock` — now references `--ce-*` tokens exclusively (`--ce-bg-workspace`, `--ce-bg-panel-raised`, `--ce-border-default`/`-subtle`/`-strong`, `--ce-text-primary`/`-secondary`/`-muted`, `--ce-accent-primary`/`-hover`/`-soft`, `--ce-state-hover`/`-warning`/`-success`, `--ce-radius-sm`/`-md`/`-pill`). No new token system was introduced; warning/danger soft-background tints use `color-mix()` derived from `--ce-state-warning`/`--ce-state-error` rather than a second hardcoded hex value. The pre-existing `--desktop-editor-*` alias layer in `globals.css` is untouched, since content components outside this sprint's scope (Asset Panel, Inspector, Preview, Timeline Workspace, AI Copilot) still depend on it.

## 7. Header

Implemented exactly the allowed set: workspace/project breadcrumb, save-state badge, undo/redo/history, refresh, Share, Export. No new backend functionality. `role="banner"`, `data-editor-focus-zone="header"`.

## 8. Tool Rail

Navigation only — 10 tool icons with active/hover state, tooltip (`title` attr), bottom compact/expand toggle, no editing logic. `aria-label`, `.ce-scroll` for overflow, `.ce-focus-ring` on every button, `data-editor-focus-zone="tool-rail"`.

## 9. Status Bar

**Honesty fix**: Zoom/Snap/Resolution/Speed previously rendered hardcoded fake values (`"100%"`, `"On"`, `"1080×1920"`, `"1x"`) with no runtime source feeding them — a direct violation of "never fake API or backend success" / "no fake information." They now render "Pending Runtime" when unset. FPS/Cursor/Duration remain real, wired from `view?.timeline` exactly as before. `role="contentinfo"`, `data-editor-focus-zone="status"`.

## 10. AI Director entry

Reserved only, per §2 — no real UI, no input, no submission path.

## 11. Focus system

7 shell-level focus zones implemented via `data-editor-focus-zone` attributes, matching the blueprint's order: `header`, `tool-rail`, `asset-panel`, `preview`, `timeline`, `inspector`, `status`. The blueprint's separate "AI Timeline" zone is not split out from "timeline" in this sprint — both AI Timeline and Manual Timeline render inside the one `EditorTimelineWorkspace` file, which is out of this sprint's scope; splitting that zone is deferred to whichever of 17.5/17.6 next touches that file (documented as a known limitation, §13).

## 12. Accessibility

Visible focus via the existing `.ce-focus-ring` utility (Sprint 17.1), applied to every interactive shell control that lacked it (header buttons, tool rail buttons, panel divider, collapse button). Landmarks: `role="banner"` (header), `role="navigation"` via `aria-label` (tool rail), `role="contentinfo"` (status bar), `role="region"` (AI Director dock). No keyboard regressions — `PanelDivider`'s arrow-key/Enter/double-click reset behavior is byte-identical to before this sprint.

## 20. Known limitations

- **AI Timeline is not yet its own focus zone** — it renders inside `EditorTimelineWorkspace`, out of this sprint's scope; the blueprint's 8th zone ("AI Timeline") is deferred to whichever of 17.5/17.6 next touches that file.
- **`usePanelCollapse` remains unused/unwired** — pre-existing since before this sprint; `useDesktopEditorLayout` manages collapse state inline instead. Not addressed here since doing so would mean changing the collapse *mechanism*, not just its token/visual layer.
- **The `--desktop-editor-*` alias layer in `globals.css` is untouched** — it remains load-bearing for every out-of-scope content component; removing it is 17.12's job, after every component that depends on it has migrated.
- **Responsive auto-narrowing is unverified against a live browser at all 4 viewports** — verified via source-level assertions (`test-desktop-editor-shell.cjs`) and the underlying math (§5), not a visual screenshot pass, consistent with this codebase's existing `.cjs`-string-assertion testing idiom (no visual/screenshot tooling exists in this project).
