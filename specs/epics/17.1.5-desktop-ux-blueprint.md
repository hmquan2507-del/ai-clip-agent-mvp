# Sprint 17.1.5 — Desktop UX Blueprint

Date: 2026-07-25

UX architecture and interaction blueprint only, as scoped. No page was redesigned, no runtime was touched, and Sprint 17.2 has not begun.

## 1. Blueprint summary

Four documents form the implementation contract for Sprints 17.2–17.8: `editor-ui-principles.md` (42 testable principles), `desktop-editor-ux-blueprint.md` (hierarchy, layout, 10 wireframes, 8 architecture diagrams, docking rules, responsive blueprint, Future Runtime Requirements, sprint boundaries), `editor-interaction-model.md` (selection model, 22-action context propagation matrix, per-surface interaction rules, keyboard/focus zones), `editor-state-matrix.md` (per-surface state tables for Editor shell, Preview, Manual Timeline, AI Decision, Inspector, AI Director).

## 2. Information hierarchy

Manual Timeline and Preview are ranked highest (protected minimums, never collapsed); AI Timeline, Inspector, Asset Panel are contextual/collapsible; Tool Rail and Header are fixed, minimal chrome. Full ranking and rationale in `desktop-editor-ux-blueprint.md` §1 and `editor-ui-principles.md` P1–P5.

## 3. Canonical layout

Single-window, single-workspace grid: Header (fixed) → Upper Zone (Tool Rail + Asset Panel + Preview + Inspector) → Timeline Workspace (AI Timeline + Manual Timeline + AI Director strip). Matches the existing `DesktopEditorShell`/`DesktopGrid` structure — this blueprint documents priorities and rules governing it, not a restructure.

## 4. Wireframes

10 named ASCII wireframes (W1–W10) cover: full desktop baseline, Asset Panel collapsed, Inspector collapsed, both side panels collapsed, AI Timeline collapsed, clip-selected state, AI decision lifecycle states, empty project, pending-AI-command state, and the 1366×768 minimum viewport.

## 5. Architecture diagrams

8 named Mermaid diagrams (D1–D8): shell composition, state ownership, the two-independent-editor-instances fact, the AI/Manual Timeline DOM-observation sync bridge, the AI decision lifecycle state machine, selection propagation, the panel resize/collapse system, and the natural-language command path. Every diagram reflects verified real architecture (`features/desktop-editor`, `features/review`, `features/ai-timeline`, `features/ai-decision-actions`) — no invented providers, services, or backend components.

## 6. Panel and docking rules

Table of default/min/max/collapsible/resizable/docking for all 7 panels, plus the collapse priority order (Asset Panel narrows → Inspector narrows → Asset Panel collapses → Inspector collapses → AI Timeline collapses; Preview and Manual Timeline never collapse).

## 7. Responsive blueprint

Documented at 1920×1080, 1440×900, 1366×768 (minimum supported), and sub-1366 fallback, reaffirming the width-math guarantee established in `frontend-responsive-system.md` (Sprint 17.1) that Preview's protected minimum always holds even with both side panels at maximum width.

## 8. Selection model

Exactly two selection concepts: the real Selection Runtime (clip/track-region selection, single authority) and AI Timeline's local `selectedBlockId` (decision selection) — related via cross-reference, never merged. 10 selection contexts enumerated in `editor-interaction-model.md` §1.

## 9. Context propagation matrix

22 actions/events × 8 columns (Selection Runtime, Manual Timeline, AI Timeline, Inspector, Preview, Asset Panel, AI Director, History), each cell marked as the authoritative writer, a derived reaction, or not-applicable.

## 10. Preview/Timeline/AI Timeline interaction rules

Preview remains playback/scrub-only in this program's scope (no new selection mechanism — flagged FRR-4). Manual Timeline's gestures remain fully owned by existing runtimes; this blueprint documents only their visual feedback. AI Timeline observes the shared time axis via `TimelineViewportContext` and never mutates Manual Timeline directly.

## 11. Inspector behavior

One contextual system with three separate data sources (Properties/AI Copilot/Decision) unified only in presentation, not merged, through Sprint 17.8 (FRR-1 defers full consolidation).

## 12. AI Director behavior

Embedded command surface, never a standalone chat page; every submission resolves to one of applied / pending-runtime / unsupported, never a silent no-op; routes exclusively through the existing `ReviewAICommandBar` → `submitAICommand` boundary.

## 13. Keyboard and focus blueprint

Defines 7 focus zones (Global, Manual Timeline, AI Timeline, Inspector, Asset Panel, AI Director input, Preview) and which zones may receive new, zone-scoped shortcuts in future sprints — existing Keyboard Runtime bindings are treated as authoritative and are not restated or redefined, avoiding any risk of drift or invented keybindings.

## 14. State matrices

Six state tables (Editor shell, Preview, Manual Timeline, AI Decision, Inspector, AI Director), each state documenting visible UI, available interactions, disabled interactions, feedback, and exit conditions — including the honest "Pending Runtime" state for AI actions with no connected adapter.

## 15. Future Runtime Requirements

7 items (FRR-1 through FRR-7) explicitly named as desired-but-unsupported and NOT scheduled into Sprint 17.2: consolidated Inspector data model, persisted panel layout, floating/multi-window panels, Preview-originated selection, connected AI Copilot/Director backend adapters, timeline minimap, and cross-highlighting beyond the shared time axis.

## 16. Sprint 17.2–17.8 boundaries

Restated from and cross-referenced with `frontend-redesign-master-plan.md`: 17.2 Shell, 17.3 Preview, 17.4 Asset Library, 17.5 Manual Timeline chrome (runtime-bounded), 17.6 AI Timeline, 17.7 Inspector, 17.8 AI Director & Copilot. Every sprint's scope explicitly excludes the runtimes and Future Runtime Requirements listed above.

## 21. Known limitations

- This blueprint documents intended presentation and interaction rules; it does not itself verify that every existing component already matches them — that verification is each implementation sprint's (17.2–17.8) own exit criteria.
- Keyboard shortcut documentation deliberately omits exact keybindings (only focus zones are defined) since exact bindings were not independently re-verified against `features/review/keyboard` source in this sprint — restating them risked drift; a future sprint touching that surface should read the source directly rather than trust this document for exact keys.
- The 22-row context propagation matrix reflects the current, real action/runtime boundaries; if a future sprint legitimately needs a new propagation path not listed here, that is a documentation gap to close explicitly, not to route around silently.

It should additionally verify its layout choices against this blueprint's panel/docking rules (§6) and wireframes W1–W4 before considering its exit criteria met.
