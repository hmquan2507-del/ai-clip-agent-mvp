# Sprint 16.10.6.1 — Desktop Editor UI/UX Refinement

Date: 2026-07-24

A UI/UX-only polish pass over the existing Desktop Editor. No new business features, no runtime redesign, no faked backend behavior — every change here is a class name, a layout constant, a label, or a new purely-presentational affordance (a "More" collections menu, an empty-state message, a tooltip that doesn't overflow the viewport).

## Before / after problems

| Problem | Fix |
|---|---|
| Preview too small | Asset panel default/max width cut from 340/520 → 300/320; Inspector 360/500 → 320/340; Tool Rail 72 → 64. Preview (the `1fr` grid column) absorbs all of that freed width automatically — no change needed to `EditorPreviewCanvas` itself. |
| Asset panel too wide / low density | Two-column grid kept, but thumbnails switched to `aspect-square` with the duration label moved from a separate text line into a badge overlaid on the thumbnail's bottom-right corner — freeing vertical space and raising the thumbnail-to-metadata ratio. |
| Timeline controls visually fragmented | The only "toolbar" this app owns outside the untouched Timeline Runtime is the header's Undo/Redo/History/Refresh cluster — now explicitly grouped (`role="group" aria-label="History"` / `aria-label="View"`) with a divider between groups. See Known Limitations for why the full History/Edit/Clipboard/View grouping the brief describes isn't fully realizable here. |
| AI Timeline has excessive empty space | Added an explicit empty state (filters hide every track / search matches nothing / no decisions yet) instead of an empty scroll area; search input narrowed slightly, filter chips no longer carry a border (just a hover background) to cut visual noise. |
| AI decision blocks hard to read | Blocks now render three width-aware tiers: below 30px → icon-only (title moves to a native `title` tooltip); 30–92px → icon + truncated title; ≥92px → icon + title + a confidence percentage. A minimum 16px hit-width keeps even zero-duration decisions clickable. |
| Inspector tabs feel unrelated | All three tabs now share one compact scrollbar utility class and the same border-subtle card treatment (softened in `AiDecisionInspector`'s cards and `PropertiesPlaceholder`'s cards) — same visual language, without touching any tab's actual behavior. |
| AI Copilot looks like a generic button list | Reorganized into the three sections the brief asks for: Quick Actions, Suggestions (now carrying an explicit "Pending runtime" badge since no adapter backs them), and a sticky **AI Director** command input (renamed from "Custom prompt", same `ReviewAICommandBar` underneath, now `position: sticky` at the panel bottom). |
| Too many visible borders | Softened several `--desktop-editor-border` (opaque) uses to `--desktop-editor-border-subtle` (translucent) across Asset Panel section dividers, Inspector's placeholder/decision cards, and filter chips; replaced the asset grid card's always-visible border with a border that only appears on hover/selection. |
| Cramped on smaller desktop screens | Verified the new minimum panel widths leave ample room at 1366×768 — see Responsive verification below. |

## Layout decisions

- **Target ranges from the brief, applied literally** to `use-desktop-editor-layout.ts`:
  - Tool Rail: `72 → 64` (expanded), compact unchanged at `48`.
  - Asset Panel: `default 340→300, min 280 (unchanged), max 520→320`.
  - Inspector: `default 360→320, min 320→300, max 500→340`.
  - Timeline Workspace height constants (`default 320, min 240, max 520`) were **left unchanged** — see Known Limitations for why "40–45% of editor height" stayed pixel-based rather than becoming a true percentage.
- Nothing about the resize/collapse **mechanism** changed — `PanelDivider`, `useLayoutResizer`, and the collapse toggles in `useDesktopEditorLayout` are untouched; only the numeric constants they read moved.

## Design tokens (Requirement 7)

Rather than invent a new palette, every requested category (App background, Panel background, Raised surface, Borders, Text hierarchy, Accent, Selection, Hover, Focus, Disabled, Error, Processing) now has an explicit, named CSS custom property in both `.desktop-editor-theme` and `.ai-timeline-theme` — each one an **alias** (`var(...)`) onto an existing color, not a new hex value:

```css
--desktop-editor-hover: var(--desktop-editor-surface-hover);
--desktop-editor-selection: var(--desktop-editor-primary-soft);
--desktop-editor-focus: var(--desktop-editor-primary);
--desktop-editor-focus-ring: rgb(124 92 255 / 45%);
--desktop-editor-disabled-text: var(--desktop-editor-text-subtle);
--desktop-editor-error: var(--desktop-editor-danger-text);
--desktop-editor-processing: var(--desktop-editor-warning-text);
```

`.ai-timeline-theme` also gained the danger/success/space/shadow token categories it was previously missing (parity with `.desktop-editor-theme`), plus its own matching alias set. `ai-decision-actions/components/decision-inspector.tsx` continues to deliberately reuse `--desktop-editor-*` tokens rather than getting a third namespace — a consolidation decision, not an oversight (there's still no `--ai-decision-*` block, by design).

A new shared `.desktop-editor-scroll` utility (thin scrollbar, both Firefox `scrollbar-width`/`scrollbar-color` and WebKit `::-webkit-scrollbar*`) is applied to every scrollable panel touched this sprint: Inspector's tab content, the Asset Library grid, AI Copilot's list, and the AI Timeline's track area.

## Responsive verification

No browser is available in this environment, so verification is arithmetic rather than visual — but the numbers are conclusive. Worst case (every resizable panel pulled to its new **maximum** width simultaneously):

```
Tool Rail (fixed) 64 + Asset Panel (max) 320 + divider 6 + divider 6 + Inspector (max) 340 = 736px
```

At the smallest listed viewport, **1366×768**: `1366 − 736 = 630px` left for Preview — comfortably usable, well above the old worst case (which was `72+520+6+6+500 = 1104px`, leaving only 262px at 1366px — the actual problem this sprint fixes). At default widths (`64+300+6+6+320=696`), Preview gets `670px` at 1366px, and correspondingly more at 1440/1600/1920. No CSS change was needed to guarantee zero horizontal overflow at any of the four target widths — the grid's `minmax(0, 1fr)` Preview column already absorbs whatever remains, and the narrowed max widths make "remains" larger everywhere.

No auto-collapse-below-a-breakpoint behavior was added (would require a `ResizeObserver` on the shell driving layout state, and the math above shows it isn't necessary to meet the stated targets) — manual collapse via the existing `PanelCollapseButton`s remains the mechanism at any width.

## Known limitations

- **Requirement 3's track-lane-height / hover-feedback / History-Edit-Clipboard-View toolbar grouping is only partially achievable.** The actual timeline track lanes, clip rendering, and toolbar (move/split/duplicate/delete/close-gap, copy/cut/paste/clear/history) all live inside `ReviewTimelinePanel` (`features/review/shell/timeline.tsx`) — explicitly listed as untouchable Timeline Runtime in every sprint through this one. This sprint's only owned "toolbar" is the Desktop Editor header's Undo/Redo/History/Refresh cluster, which is now grouped (History/View); there is no "Edit" or "Clipboard" group to visually organize because those controls are not exposed to `desktop-editor` at all today. Increasing track lane height, adding clip hover feedback, and improving playhead visibility inside the real timeline would all require editing that file — flagged here rather than worked around unsafely.
- **Timeline Workspace height stayed pixel-based, not literally 40–45%.** The resize mechanism (`PanelDivider` + `useDesktopEditorLayout`) stores an absolute pixel height with min/max clamps; converting to a true percentage-of-available-height would change how the resize math and collapse-to-64px interact, a bigger change than a visual refinement pass warrants. The existing 320px default/240–520px range already lands in a reasonable proportion at common editor heights.
- **No real browser was available to visually verify** the four target viewport widths — verification here is arithmetic (panel min/max widths vs. viewport width), which is conclusive for "no horizontal overflow" but doesn't confirm subjective readability/spacing at each size.
- **"Preview controls become visually quieter when idle"** was not implemented: the actual play/pause/volume/fit controls live inside `ReviewPreviewStage` (Review Runtime, `features/review/shell/workspace-panels.tsx`), which `EditorPreviewCanvas` wraps but does not own. There is no Desktop-Editor-owned preview chrome to dim.
- **The Asset Panel's "More" collections menu is a new, lightweight popover** (click-outside via a full-screen backdrop `div`, no external library) — functionally complete but not extensively cross-browser tested beyond this sandbox's build/lint pass.
