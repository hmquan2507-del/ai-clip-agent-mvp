## 2. Critical UX findings

1. **Three parallel token systems** (`--review-*`/`--desktop-editor-*`/`--ai-timeline-*`) duplicate the same visual intent under different variable prefixes.
2. **A fourth, un-tokenized legacy visual language** (`components/ui/*` + every `DashboardShell` page) uses literal Tailwind colors with no theme awareness at all.
3. **Four routes are non-functional placeholders wearing production chrome** (`/productions`, `/ai-queue`, `/styles`, `/settings`) — `/settings` literally labels its cards "Configuration placeholder."

(Full severity table with all 18 findings in `frontend-ux-visual-audit.md`.)

## 3. Design direction

One line: a professional, AI-first desktop video editor (DaVinci/Premiere/Final Cut/Descript/OpusClip as *interaction* references, never cloned visually) — never a SaaS dashboard, landing page, ChatGPT clone, disconnected card collection, or an enlarged mobile UI. Ten principles govern every future sprint (Preview/Timeline lead hierarchy; AI visible but restrained; surface contrast before borders; color = state never decoration; dense-but-readable controls; no generic cards/gradients/rounded excess/decorative motion/oversized marketing type inside the editor). Full text in `frontend-design-direction.md`.

## 4. Tokens created or updated

One semantic namespace, `--ce-*` ("Clip Editor"), added to `frontend/src/app/globals.css` at `:root` (available everywhere, no theme class required):

- **Color**: background (6), border (4), text (5), accent (4), state (8), timeline (7), AI decision lifecycle (9) = 43 color tokens.
- **Typography**: 13 roles (display/pageTitle/panelTitle/sectionTitle/body/bodyCompact/label/metadata/caption/timelineLabel/button/input/code), each as 3 CSS variables + 1 ready-to-use utility class (`.ce-text-*`).
- **Spacing**: 7-step scale (2xs–2xl).
- **Editor dimensions**: header/tool-rail/asset-panel/inspector/timeline-toolbar/track/AI-timeline/control-height/icon-size — 20 tokens, matching the numbers already verified in Sprint 16.10.6.1 (not new values, just now named tokens).
- **Radius** (4 steps), **elevation** (3 shadows), **motion** (3 durations + 3 easings).
- Existing `--review-*`/`--desktop-editor-*`/`--ai-timeline-*` values that are byte-identical to a `--ce-*` token are now aliased onto it in place (accent/warning/danger/success colors, timeline clip colors, playhead color) — a provable no-op visually, confirmed by an unchanged production build and unchanged regression results. Values that genuinely differ (e.g. AI Timeline's distinct `#a855f7` accent) are left as literal, explicitly documented intentional deviations.
- Reduced-motion coverage extended app-wide (previously only `.review-editor-theme` was covered) via a new, additive root-level `prefers-reduced-motion` rule — the old scoped rule is left in place, unmodified.
- New shared utilities: `.ce-surface-*` (6 elevation classes), `.ce-state-selected`/`.ce-state-hover`/`.ce-state-disabled`/`[data-ce-disabled]`, `.ce-focus-ring`, `.ce-scroll` (unified thin scrollbar, supersedes the theme-scoped `.desktop-editor-scroll` for any new consumer while leaving the old one working).

## 13. Known limitations

- **Aliasing is partial, not exhaustive.** Only byte-identical values were aliased from the three legacy theme scopes onto `--ce-*` this sprint (accent/state colors, timeline clip colors). Background/surface/border/radius values differ slightly across the three scopes today (by design — they were tuned independently) and are *not* force-aliased, since doing so would change visible output — that reconciliation is explicit 17.2 work (Desktop Editor Shell Redesign), not silently done here.
- **No component code was migrated onto the new tokens.** Per the sprint's explicit "implement only the foundation" constraint, every `.tsx` component still references the legacy `--review-*`/`--desktop-editor-*`/`--ai-timeline-*` variables (which now resolve through the alias layer where applicable) — visual migration is 17.2+.
- **The Manual Timeline toolbar-grouping / track-lane-height items from the UX audit (F9) remain unresolved and are explicitly *not schedulable*** without a separate, explicitly-approved exception to the Timeline Runtime boundary — documented clearly rather than worked around.
- **No visual/screenshot regression tooling exists or was added** — verification remains build/typecheck/the existing `.cjs` string-assertion idiom, consistent with this codebase's established (and only) testing pattern.
- **Full WCAG contrast audit, icon-label sweep, and roving-tabindex work are deferred to Sprint 17.11** per the Accessibility System's explicit fixed-now-vs-deferred table — only the CSS-only reduced-motion gap was closed in 17.1.

## 14. Recommended start point for Sprint 17.2

**Desktop Editor Shell Redesign** (`frontend-redesign-master-plan.md` §17.2) — cut `features/desktop-editor` and `features/ai-timeline` component class references directly onto `--ce-*` (bypassing the alias layer where their current values differ from the canonical `--ce-*` set), and apply "surface contrast before borders" to the shell chrome. This is the lowest-risk, highest-context surface (six prior sprints of established familiarity), directly serves the "prioritize Preview and Timeline" instruction carried through every sprint in this program, and its exit criteria (visual equivalence-or-better + all regression scripts green + responsive math re-verified) are the same low-risk pattern already proven in 16.10.6.1.
